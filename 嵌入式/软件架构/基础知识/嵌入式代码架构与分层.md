## 3. 分层结构

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-01-分层架构注释图.jpg]]

各个层级之间是解耦的关系。

| 层 | 含义 | 说明 |
| --- | --- | --- |
| BSP | 板级支持驱动程序（Board Support Package） | MCU 和板上外设器件（比如 MPU6050）的通信与交互过程 |
| Core | MCU 驱动程序 | 面向 MCU 编程，初始化 MCU 内部的外设（时钟、IIC、SPI 等），包含 `main.c` |
| Drivers | 厂商 SDK 程序 | MCU 厂商和 MCU 内的 CPU 厂商提供的驱动库，用来对 CPU 和片上外设编程 |
| Middlewares | 中间件 | 抽象程度很高，能在各个项目中通用：LVGL、数学库、快速傅里叶变换库 |
| OS | 操作系统层 | FreeRTOS 等 |
| SYSTEM | 系统配置层 | 对系统定义整体的宏；对全局系统有影响的参数和文件放在这个目录下 |
| 业务层（APP） | 应用逻辑 | 结合业务实现具体的应用逻辑，一般是一个个 `xxx_task.c/.h` 文件存放的位置 |

BSP 驱动有时分两种：

1. 在裸机（有限状态机）情况下写的驱动程序；
2. 在操作系统下写的驱动程序。

### 不要跨层操作

设计每层代码时，一定避免跨层操作，原因如下：

- 跨层执行会破坏分层解耦。修改其中一层代码后，为了让功能实现必须跨层修改，逻辑不清晰，架构混乱。
- 下层某些操作可能在中断中执行，部分中断 RTOS 无法管理，会造成数据溢出、数据完整性缺失、影响其他硬件工作、RTOS 中的任务无法执行等问题。
- 可能产生线程安全问题。比如 APP 线程向驱动线程传递了阻塞的回调函数，驱动线程被阻塞，导致其他消费者线程的任务执行被延迟。

## 4. 程序解耦

### 为什么要解耦

1. 多人开发、并行工作
2. 帮助问题的定位
3. 轮子的复用
4. 关注点分离
5. 资源管理
6. 性能优化
7. 模块自检功能
8. 安全性
9. 标准化
10. 调试和测试

### 模块设计规则

1. 高内聚
2. 自检
3. 声明所有资源
4. 接口是精心设计和定义的
5. 模块包含「作者」「版本」以及「编译运行环境」信息

## 6. 如何进行程序解耦

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-04-技术面要求与接口结构体.jpg]]

### 技术面要求

1. 指针（函数指针、空指针、结构体指针等）
2. 结构体（struct）
3. 联合体（union）
4. 枚举（enum）
5. 接口和回调函数（callback）
6. 动态分配内存（malloc）
7. 预处理器指令（宏定义、条件编译、文件包含、错误指示）
8. 模块划分

### 驱动程序实现步骤（以 MPU6050 为例）

**实现方向**：我们的工作实际是在实现 BSP 中的 HAL 层，HAL 实现器件寄存器、器件状态的控制。与 MCU 外设不同的是，BSP 中往往要用到 MCU 的部分通信外设（IIC、SPI 等），所以既要清楚外设模块的寄存器和工作模式，也要了解其通信方式。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-05-实现方向BSP中的HAL层.jpg]]

**步骤一：确认资源信息**。确认模块型号（MPU6050）和所需 MCU 功能（IIC、延时、中断）。信息来源是模块芯片手册、硬件原理图、MCU 芯片手册。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-06-步骤一确认资源信息.jpg]]

**步骤二：确认对象之间的关系**。高级对象代表整个模块；低级对象封装更基本、更接近硬件层面的功能；高级对象一般通过组合或调用多个低级对象来实现功能。例如高级对象 MPU6050 调用低级对象 IIC 读写寄存器，调用低级对象外部中断获悉数据采集完成。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-07-步骤二确认对象关系.jpg]]

**步骤三：实现具体模块功能**。模块对象通过自己的成员函数调用这些低级对象完成具体任务，实现模块对象与低级对象的链接（参考驱动框架头文件 `mpuxxxx.h`）。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-08-步骤三实现模块功能.jpg]]

**步骤四：实现程序自诊断**。高级模块每个任务最好都定义返回值，问题发生时可以及时定位问题所在（参考 `mpuxxxx.c`）。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-09-步骤四程序自诊断.jpg]]

**实现驱动程序的线程安全**（原课件同样标为「步骤四」）。独立性：本模块出现问题时不影响系统正常运行。资源性：避免重复调用造成内存浪费；驱动出现问题时及时回收已产生的内存资源。图中示例展示了互斥锁的用法，以及创建队列失败时应及时释放队列所占空间。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-10-线程安全.jpg]]

**步骤五：用面向对象的方式实例化**。前面讲的都是框架整体模型，还没有把模型实例化到模块中。高级对象编写的驱动架构需要分配实际的内存空间，并实际调用 MPU 库函数和 MCU HAL 库函数。

![[嵌入式/软件架构/附件/嵌入式代码架构与分层-11-步骤五面向对象实例化.jpg]]

原文档中给出的一份分层总结（文档作者的作答，供对照）：

- Driver 层：主要用于操作底层的硬件、寄存器。
- Core 层：主要是初始化底层硬件，包含 `main.c`。
- BSP 层：主要用于 BSP 初始化，通过一些通讯协议与外设通讯，并返回对应的数据。
- 操作系统层：用于 IO 控制，调用 BSP 中的程序读取数据，并将数据缓存发送给 APP。
- 中间件：通用型第三方库，比如 LVGL、Modbus 等移植过来使用。
- APP 层：进行任务调度和进程间的通讯。
