## 题目

### 1. static 关键字的作用

- [ ] 能脱稿讲清楚
- **来源**：[[嵌入式/面经/面试记录/智元机器人-嵌入式-一面|智元机器人-嵌入式-一面]] 第 8 题。
- **口述版答案**：分三种用法讲。
  - 修饰局部变量：变量从栈上挪到静态存储区，只初始化一次，函数返回后值还在，下次调用接着用。作用域不变，仍然只能在函数里访问。
  - 修饰全局变量：把它的可见范围限制在当前源文件，其他文件用 `extern` 也访问不到。
  - 修饰函数：同样是限制在当前源文件内可见。
  - 一句话总结：对局部变量改的是生命周期，对全局变量和函数改的是链接属性（从外部链接变成内部链接）。
  - 嵌入式里的用途：模块内部的变量和函数都加 `static`，只把接口暴露在头文件里，避免不同文件重名，也是一种封装。
- **常见追问**：
  - 静态变量没初始化时值是多少：0。未初始化或初始化为 0 的放在 `.bss` 段，初始化为非 0 的放在 `.data` 段。
  - 带静态局部变量的函数有什么问题：不可重入，在中断和任务里同时调用、或多个任务同时调用会出错。
  - 头文件里定义 `static` 变量会怎样：每个包含它的源文件各有一份独立的副本，互不影响，通常不是想要的结果。
- **易错点**：说“静态局部变量的作用域变成全局”。变的是生命周期，作用域没变。
- **深入阅读**：[[基础知识/C语言/C语言索引|C语言]]

### 2. volatile 关键字的作用

- [ ] 能脱稿讲清楚
- **来源**：[[嵌入式/面经/面试记录/智元机器人-嵌入式-二面|智元机器人-嵌入式-二面]] 第 12 题。
- **口述版答案**：
  - 作用：告诉编译器这个变量可能在当前代码看不到的地方被改变，每次访问都必须真的去读写内存，不能把值缓存在寄存器里，也不能把看似多余的读写优化掉。
  - 三个典型场景：
    - 硬件寄存器：值由硬件改变，读写本身可能有副作用。
    - 中断和主循环共享的变量：比如中断里置标志位、主循环里轮询。不加的话，开了优化后主循环可能只读一次，之后一直用旧值，变成死循环。
    - 多个任务共享的变量。
- **常见追问**：
  - `volatile` 能保证原子性吗：不能。`cnt++` 仍然是读、加、写三步，中间可能被中断打断，需要关中断或加锁。
  - `const volatile` 能一起用吗：能。表示程序不应该去写它，但它的值会自己变，例如只读的状态寄存器。
  - `volatile int *p` 和 `int * volatile p` 的区别：前者是指向的数据易变，后者是指针本身易变。寄存器访问用前者。
  - 不开优化时不加 `volatile` 也没问题，为什么：不优化时编译器每次都老实访问内存，问题被掩盖了，一开优化就暴露。
- **易错点**：把 `volatile` 当成线程安全的手段。它只管“每次都访问内存”，不管互斥，也不管多核之间的执行顺序。
- **深入阅读**：[[基础知识/C语言/C语言索引|C语言]]

### 3. 多核 MCU 上的内存屏障

- [ ] 能脱稿讲清楚
- **来源**：[[嵌入式/面经/面试记录/智元机器人-嵌入式-二面|智元机器人-嵌入式-二面]] 第 13 题，紧接着 volatile 问的。
- **口述版答案**：
  - 背景：为了性能，编译器会调整指令顺序，CPU 也可能乱序执行、把写操作先放在缓冲里。单核上程序自己看不出差别；多核共享内存时，另一个核看到的写入顺序可能和代码顺序不一致。
  - 内存屏障是一类指令，强制屏障之前的内存访问先完成，之后的才能开始，用来保证顺序和可见性。
  - ARM 上有三条：DMB（数据内存屏障，保证内存访问的先后顺序）、DSB（数据同步屏障，等前面的访问全部完成再往下执行）、ISB（指令同步屏障，清空流水线，让之前对系统寄存器的修改生效）。
  - 典型场景：核间无锁队列里“先写数据、再更新写指针”，两步之间要有屏障，否则另一个核可能先看到新指针、读到旧数据。
  - 实际写代码一般不直接写屏障指令，而是用 C11 的原子操作或者系统提供的锁、核间通信接口，它们内部带了屏障。
  - 没用过就如实说，再讲上面这些理解。
- **常见追问**：
  - 单核 Cortex-M 上用得到吗：用得到 DSB 和 ISB，比如修改 CONTROL 寄存器、配置 MPU、重定位向量表之后，或进入休眠指令之前。
  - `volatile` 能代替内存屏障吗：不能，`volatile` 只约束编译器对这个变量的访问，不约束 CPU 在多核之间的可见顺序。
- **易错点**：把内存屏障和内存保护（MPU）混为一谈。

### 4. 手写链表插入

- [ ] 能脱稿讲清楚
- **来源**：[[嵌入式/面经/面试记录/智元机器人-嵌入式-一面|智元机器人-嵌入式-一面]] 第 9 题，手写代码。原帖没说是头插、尾插还是按位置插，动笔前先问清楚。
- **口述版答案**：先说思路再写。
  - 在某个节点后面插入只有两步，顺序不能反：先让新节点指向后继，再让前驱指向新节点。
  - 头部插入会改变头指针，所以函数要么返回新的头指针，要么传头指针的地址（二级指针）。
  - 参考代码（单链表，头插和在指定节点后插入）：

    ```c
    #include <stdlib.h>

    typedef struct Node {
        int data;
        struct Node *next;
    } Node;

    /* 头插：传入头指针的地址，成功返回 0 */
    int list_push_front(Node **head, int data)
    {
        Node *node = malloc(sizeof(Node));
        if (head == NULL || node == NULL) {
            free(node);
            return -1;
        }
        node->data = data;
        node->next = *head;
        *head = node;
        return 0;
    }

    /* 在 pos 节点后面插入，成功返回 0 */
    int list_insert_after(Node *pos, int data)
    {
        if (pos == NULL) {
            return -1;
        }
        Node *node = malloc(sizeof(Node));
        if (node == NULL) {
            return -1;
        }
        node->data = data;
        node->next = pos->next;   /* 先接后继 */
        pos->next = node;         /* 再改前驱 */
        return 0;
    }
    ```

- **常见追问**：
  - 尾插怎么写：遍历到最后一个节点再调用上面的后插；空链表时等同于头插。想要 O(1) 就额外维护一个尾指针。
  - 按顺序插入有序链表：用二级指针从头往后找到第一个不小于新值的位置，可以把“插在头部”和“插在中间”统一成一段代码。
  - 双向链表插入要改几个指针：四个。
  - 嵌入式里不想用 `malloc` 怎么办：节点由调用者提供（静态数组或内存池），插入函数只负责改指针。FreeRTOS 和 Linux 内核的链表都是这种做法。
- **易错点**：
  - 两步写反，先改了 `pos->next`，后继就丢了。
  - 没处理空指针和 `malloc` 失败。
  - 头插函数只传一级指针，函数里改的是副本，外面的头指针没变。
- **深入阅读**：[[基础知识/数据结构与算法/数据结构与算法索引|数据结构与算法]]
