# 软件与工具链

入门必知 · 12 个词条

## 7.1 开发环境基础

### 1. Python 与 C++（具身常用编程语言）（Python and C++）

**概念：** 机器人开发中常配合使用的两门语言。Python 适合数据处理、深度学习训练和快速实验；C++ 常用于驱动、控制、规划等需要较高效率和可控时延的部分。常见流程是用 Python 训练模型，再由 C++ 程序加载执行，或由 Python 调用底层 C++ 库。

**例子：** 用 Python 在 Isaac Lab 里训练四足行走策略，导出成 ONNX（通用的神经网络模型交换格式）后在 C++ 控制程序里以固定频率推理并下发电机指令。

### 2. GitHub（代码托管平台）（GitHub）

**概念：** 基于 Git 仓库的代码托管与协作平台，项目通常包含代码、README、许可证和 Issues 讨论。Git 负责版本控制，GitHub 提供在线托管及协作功能。复现机器人项目时，通常先获取官方仓库，按说明安装依赖并运行示例，再通过 Issues 查找已知问题。

**例子：** Hugging Face 的 LeRobot 代码在 github.com/huggingface/lerobot，git clone 后按 README 安装即可。

### 3. CUDA（Compute Unified Device Architecture，CUDA）

**概念：** 英伟达的 GPU 并行计算平台和编程模型，包含编译工具、运行库及相关计算库。PyTorch、GPU 仿真和推理加速工具可通过它利用显卡算力。配置环境时需区分显卡驱动、框架所用运行库和本机 Toolkit，并核对版本兼容关系。

**例子：** 在 Python 里运行 torch.cuda.is_available()，返回 True 才说明 PyTorch 能用上 GPU。

## 7.2 ROS 2 入门

### 4. 机器人操作系统（Robot Operating System，ROS）

**概念：** 面向机器人的开源中间件和工具集合，将驱动、感知、规划等功能组织为节点，通过消息通信协作。生态中提供坐标变换、可视化、数据记录、导航和规划等工具。ROS 1 与 ROS 2 的通信和构建方式不同，使用教程和软件包时需要确认对应版本。

**例子：** 用 roslaunch 一次启动相机驱动、机械臂驱动和 MoveIt 规划节点，再在 RViz 里拖动目标位姿让机械臂运动。

### 5. ROS 2（Robot Operating System 2，ROS 2）

**概念：** 对 ROS 1 重新设计的机器人软件框架，保留节点、话题、服务和动作等概念，常通过 DDS 实现分布式通信与节点发现。它提供 QoS 配置及实时性、安全性相关机制。接口和构建工具与 ROS 1 不同，迁移时需要适配代码和依赖。

**例子：** 在 Ubuntu 上装好 ROS 2 后运行 ros2 topic list，就能列出当前系统里所有活跃的话题。

### 6. 节点（Node (ROS)）

**概念：** ROS 中的基本软件功能单元，通常分别负责相机采集、目标检测、规划或电机驱动等任务。节点通过话题、服务和动作交换消息，可分布在同一台或多台计算机上。这样便于模块独立开发、替换和调试，ROS 2 节点常使用 Python 或 C++ 编写。

**例子：** 一个相机驱动节点发布图像，一个检测节点订阅图像并发布物体位置，一个控制节点据此让机械臂去抓。

### 7. 话题（Topic (ROS)）

**概念：** ROS 中按名称和消息类型组织的发布—订阅通信通道，一个话题可以连接多个发布者和订阅者。它适合图像、点云、关节状态和速度指令等连续数据流；一次请求并返回结果常用服务，需要进度反馈或取消的长任务常用动作。

**例子：** 底盘驱动节点订阅 /cmd_vel 话题（Twist 类型速度指令），键盘遥控节点往这个话题发布速度，底盘就会跟着动。

## 7.3 机器人模型与坐标系

### 8. 统一机器人描述格式（Unified Robot Description Format，URDF）

**概念：** 用 XML 描述机器人结构的格式：link 记录连杆外观、碰撞形状和质量惯量，joint 记录连接关系、关节类型、转轴和限位，整体形成运动学树。它可用于显示模型、计算运动学和导入仿真；树状表达对闭链机构有限制，重复结构常用 Xacro 宏简化。

**例子：** 机器人厂商通常随机器人提供 URDF 和网格文件，把它导入 Isaac Lab 就能在仿真里训练这台机器人的策略。

## 7.5 连接真机与实时系统

### 9. 软件开发工具包（Software Development Kit，SDK）

**概念：** 厂商提供的一组开发材料，通常包含接口库、API 文档、示例代码、驱动和工具。机器人开发者通过它读取状态、获取图像并下发运动指令。SDK 开放到哪一层，决定了能否直接控制关节或力矩，还是只能调用预设的高层动作。

**例子：** 宇树 G1 通过 unitree_sdk2 读取各关节角度并下发电机指令，研究者据此部署自己训练的运动控制策略。

## 7.9 深度学习与机器人学习库

### 10. PyTorch（PyTorch）

**概念：** 以张量运算和自动求导为核心的开源深度学习框架，支持用 Python 构建、训练和部署神经网络，并可利用 GPU 加速。机器人学习中的许多策略与工具库基于它。常见工作包括组织数据、定义模型、执行优化循环，以及保存和加载训练检查点。

**例子：** import torch 后用 model.to('cuda') 把网络放到 GPU 上训练，训练完用 torch.save 保存检查点。

### 11. LeRobot（LeRobot (Hugging Face)）

**概念：** Hugging Face 的开源机器人学习工具库，基于 PyTorch，提供统一数据格式和演示采集、策略训练、评测、真机运行等流程。可配合低成本机械臂完成模仿学习实验，并使用 ACT、扩散策略等现成实现，减少从零搭建数据和训练管线的工作。

**例子：** 用两台 SO-101 机械臂做主从遥操作录制几十条抓取演示，再用 LeRobot 训练一个 ACT 策略并在真机上运行。

## 7.11 部署与推理加速

### 12. 推理部署（Inference Deployment）

**概念：** 把训练好的模型放到实际硬件和运行系统中，接收实时传感器输入并输出动作。这里的推理指模型前向计算，部署需要满足算力、内存、通信和控制时序要求。模型可在机器人本体上运行，也可通过远程策略服务器返回动作，量化和推理引擎可用于加速。

**例子：** 把微调好的 π0 放在一台带 GPU 的工作站上跑策略服务器，机器人每隔一段时间发送图像和关节状态、取回一段动作。
